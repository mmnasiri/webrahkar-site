# دموی تعاملی برنامه‌ریزی ارسال سفارش‌ها

این دمو برای میزبانی ایستا در GitHub Pages یا Cloudflare Pages ساخته شده است. از Django، Python، پایگاه داده، API تجاری یا سرور اختصاصی استفاده نمی‌کند؛ محاسبه در مرورگر اجرا می‌شود.

## مدل
- ۱۰ سفارش و ۳ خودرو؛ تقاضای هر سفارش، ظرفیت خودرو، زمان خدمت و مهلت تحویل در مدل هستند.
- هر سفارش دقیقاً یک بار به یکی از خودروها تخصیص داده می‌شود.
- هر خودرو یک مسیر از انبار مرکزی و بازگشت به انبار دارد.
- اگر زمان شروع خدمت از مهلت تحویل عبور کند، سفارش دیرکرد دارد.
- تابع هدف به‌صورت واژگانی است: (۱) بیشینه‌کردن تعداد تحویل‌های به‌موقع، (۲) کمینه‌کردن مجموع دقیقه‌های تأخیر، (۳) کمینه‌کردن مجموع اضافه‌کاری خودروها، (۴) کمینه‌کردن فاصلهٔ شبکه‌ای، و (۵) کمینه‌کردن زمان حرکت.
- فاصله بر مبنای مسیر شبکه‌ای ساده‌شده (فاصلهٔ منهتنی) و زمان سفر وابسته به ترافیک کلی و عبور از محورهای پرتردد محاسبه می‌شود.

## چرا جواب دقیق است؟
الگوریتم همهٔ ترتیب‌های مجاز هر مسیر را با رعایت ظرفیت بررسی می‌کند و بهترین مسیر را برای هر زیرمجموعهٔ سفارش‌ها و هر خودرو نگه می‌دارد. سپس برنامه‌ریزی پویای زیرمجموعه‌ها همهٔ تقسیم‌های ممکن سفارش‌ها بین خودروها را مقایسه می‌کند. معیارها جمع‌پذیرند؛ بنابراین انتخاب بهترین مسیر هر زیرمجموعه و سپس بهترین تقسیم ناوگان، جواب دقیقِ همین مدل محدود را می‌دهد. الگوریتم مسیرها را از پیش ذخیره نمی‌کند؛ جابه‌جایی مشتری، ترافیک، مهلت یا ظرفیت باعث محاسبهٔ مجدد می‌شود.

دمو علاوه بر جواب دقیق، یک روش مقایسه‌ای ساده (تخصیص ظرفیت با Best-Fit و سپس انتخاب نزدیک‌ترین سفارش) را نیز از روی ورودی جاری محاسبه می‌کند. برنامهٔ ساده صرفاً برای مقایسه است و جواب بهینه معرفی نمی‌شود.

## محدودیت‌های صریح
این نقشه واقعی نیست و از سرویس نقشه یا ترافیک زنده استفاده نمی‌کند؛ فاصله‌ها و زمان‌ها از یک مدل آموزشیِ شبکه‌ای محاسبه می‌شوند. بهینه‌بودن فقط نسبت به همین مدل، تابع هدف و ۱۰ سفارش برقرار است. برای بهره‌برداری واقعی باید شبکهٔ راه‌ها، زمان‌های ترافیک در طول روز، پنجره‌های زمانی عملیاتی، هزینه‌ها و قواعد سازمان به مدل افزوده شوند. این الگوریتم برای این اندازهٔ کوچک طراحی شده و جایگزین حل‌گر عمومی برای مسائل بزرگ نیست.

## اجرا و میزبانی
تمام فایل‌ها در همین پوشه‌اند. فایل index.html را از طریق یک وب‌سرور استاتیک باز کنید (برای مثال GitHub Pages). حل‌گر در solver.js است و solver.worker.js آن را در Web Worker اجرا می‌کند تا رابط کاربر هنگام حل پاسخ‌گو بماند. app.js رابط، تغییر پارامترها و نمایش مسیرها را مدیریت می‌کند.
